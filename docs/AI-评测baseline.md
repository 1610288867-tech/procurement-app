# 知识库评测：baseline 与两轮真实发现

> **这份文档回答一个问题**：这套 RAG 现在到底什么水平，问题出在哪。
>
> **数据来源**：`backend/scripts/knowledge_eval.py` 的真实运行结果。
> 原始数据在 `backend/scripts/eval/` 下（含逐条明细，可复核）：
> `baseline-hash-256.json`（哈希时代）、`baseline-bge-small-zh.json`（真 embedding）。
>
> **默认配置现在是真 embedding。** 两个配置的完整对比见下面「结论」一节。

---

## 零、结论先写在这里

| | 哈希 @ 阈值 0.15（最初） | **真 embedding @ 阈值 0.50（现在）** |
| --- | --- | --- |
| Recall@5 | 1.000 | 1.000 |
| **MRR** | 0.879 | **0.932 ~ 0.955** |
| **NDCG@5** | 0.910 | **0.950 ~ 0.966** |
| **实际回答成功率** | 0.864 | **1.000** |
| 能答却被拒答 | **3 条** | **0 条** |
| 无答案问题被正确拦住 | 3/5 | 3/5 |

**换真 embedding 同时修好了两个相反方向的毛病。** 哈希时代的问题是
"该答的不答"（口语化问题相似度只有 0.025，被阈值拦下）；
而**只换模型、不动阈值**会走到另一个极端 ——
"不该答的全答了"（语义相近的无关片段也拿到 0.4+，5 条无答案问题全被硬答，
这一点**实测过**，见第三节问题 2）。
**结论：阈值与 embedding 必须一起标定，不能只换一个。**

## 一、评测集长什么样

`backend/scripts/eval/knowledge_eval_cases.json`：**27 条用例 + 3 份制度文档**。

| 类别 | 条数 | 考什么 |
| --- | --- | --- |
| `fact` 事实查询 | 8 | 条文里的数字与流程（"超过十万元应当怎么样"） |
| `condition` 条件查询 | 6 | 条件与否定（含一条**边界题**：刚好十万元算不算"超过"） |
| `cross_version` 跨版本 | 3 | 知识库同时放着《差旅费管理办法》2025 版（已失效）与 2026 版，**只应命中现行版** |
| `colloquial` 口语化 | 5 | 用户不会用条文原词（"多少钱要招标啊"） |
| `unanswerable` 无答案 | 5 | 知识库里没有的问题，**必须说"没找到"而不是硬答** |

**两个关键设计**（改这个评测集前必须先读）：

1. **定位标记法**：制度文本里埋了 `[[c2]]` 这样的标记，运行时映射成真实 chunk id。
   好处是**改切分参数不用改评测集** —— 而写死 chunk 编号的评测集改一次切分就全废；
2. **必须有"无答案问题"与"跨版本问题"**：
   前者验证"不知道就说不知道"，后者验证"不引作废条文"（引错比查不到更糟）。

> 升维减少了哈希碰撞，所以排序确实变好了一点，这是可复现的。

### 怎么读这张表

**检索层好看得出乎意料**（Recall@5 = 1.000）—— 但**这不代表 embedding 好**，
因为评测集只有 3 份短文档、27 个片段，而"要的那一片"往往是**唯一**含那个关键词的片段。
**小规模语料上，字面重合就够了。** 换句话说：**这个 1.000 不能推出"检索没问题"**，
它只说明"在这套语料上没问题"。诚实的结论要连同语料规模一起说。

**真正有信息量的是分桶后的 `top_score` 分布**：

| 类别 | top_score 最低 | 最高 |
| --- | --- | --- |
| `fact`（能答） | 0.400 | 0.642 |
| `condition`（能答） | 0.192 | 0.346 |
| `cross_version`（能答） | 0.351 | 0.499 |
| `colloquial`（能答） | **0.025** | 0.221 |
| `unanswerable`（**不该答**） | 0.042 | **0.362** |

**"能答"与"不该答"的分数区间完全重叠** ——
`colloquial` 最低 0.025，而 `unanswerable` 最高 0.362。
**不存在任何一个阈值能把它们分开。**

## 三、首次发现的四个问题（按重要程度）

### 问题 1（最重要）：阈值与 embedding 不匹配，导致"检索到了却拒答"

**现象**：`有答案问题误拒答 3 条` —— 三条口语化问题全部被拒：

| 用例 | 问题 | top_score | 结果 |
| --- | --- | --- | --- |
| L-01 | 多少钱要招标啊？ | 0.025 | 拒答 |
| L-03 | 东西收得不合格怎么办？ | 0.131 | 拒答 |
| L-05 | 想买东西但是账上没钱，能不能先买了再说？ | 0.076 | 拒答 |

**根因**：本地哈希 embedding 靠**字面重合**，而这三条问题与条文**几乎没有共同词**。
阈值 0.15 正确地拦住了它们 —— **拒答是系统在正确工作**，
错的是"这个 embedding 配不上这个阈值"。

→ 这正是 `embedding.py` 里早就写着的那句话被**量化证实**：
"**别用它判断 RAG 设计好不好，它只能验证链路通不通。**"

**同时暴露的隐患**：`unanswerable` 里的 U-05（"采购金额超过一亿元的，需要经过董事会审批吗？"）
top_score 高达 **0.362** —— 它**越过了阈值、调用了模型**（虽然兜底只摘了原文，
没编出"董事会"这一层）。**这是"该拦没拦"**：
一旦接上真模型，它很可能会把条文里没有的审批层级**编出来**。
这条用例是我特意设计的，它证明了**无答案问题里最难的一类不是"完全不相关"，
而是"字面高度相关但条文里没有那个答案"**。

### 问题 2：`Precision@5` 偏低 —— 一半左右的上下文是噪声

哈希时是 0.333（每次检索回 5 条、平均 1.7 条相关），真 embedding 下是 0.500。
后果有两个：① 上下文预算被浪费；② 真对话模型更容易被无关片段带偏。
→ 这是**重排（rerank）与混合检索**要解决的问题，也是它们的效果对比基准。

### 问题 2b：`MRR = 0.879` 而不是 1.000（**哈希时代**）—— 部分"要的那一片"没排第一

`MRR` 计入 20 条（比 Recall 的 22 条少 2 条，因为那 2 条**检索没返回任何结果**——
见下面的口径说明）。0.879 说明**有一批用例的正确片段被排到了第 2 位之后**，
而 Recall@5 是 1.000 —— 也就是"找到了，但没排在最前"。
这正是重排的用武之地，也是**真 embedding 修好的第一件事**（0.879 → **1.000**）。

> **MRR 的口径**：`mean_reciprocal_rank` **剔除"没返回任何结果"的用例**。
> MRR 问的是"第一个正确结果排在第几"，一次根本没返回结果的查询在这条指标上
> **没有位置可言**；把它按 `RR = 0` 计入会让 MRR 退化成"命中率"的另一种写法，
> 并**系统性压低**它（实测：算进去 0.879 → 剔除后 0.977）。
> 这与"召回为空时 Recall 返回 `None`"是同一条纪律：**不适用不能当成 0**。

### 问题 3（**换成真 embedding 之后新出现的，最值得记的一条**）：阈值必须重新标定

这是本次改动里最重要的一课，因为它**方向与哈希时代完全相反**：

| 配置 | 症状 |
| --- | --- |
| 哈希 @ 0.15 | **该答的不答** —— 口语化问题 top_score 只有 0.025，3 条能答的也被拒 |
| 真 embedding @ **0.15**（照旧） | **不该答的全答了** —— 语义相近的无关片段也拿到 0.4+，**5 条无答案问题全部越过阈值被硬答** |
| 真 embedding @ **0.50**（标定后） | 误拒 0 条、正确拦住 3/5 —— 两边都正常 |

**根因**：`min_score` 是"要不要回答"的**唯一判据**，而分数的量纲由 embedding 决定。
换模型就换了量纲，阈值不动必然错。

**标定要数据，不能拍**（实测分布，27 条）：

| | 最低 | 最高 |
| --- | --- | --- |
| 能答的 22 条 | 0.5228 | 0.8405 |
| 无答案 5 条 | 0.3562 | 0.6533 |

阈值扫描的结果（`--min-score` 逐个试）：

| 阈值 | 能答被误拒 | 无答案被拦 |
| --- | --- | --- |
| 0.45 | 0 | 3/5 |
| **0.50** | **0** | **3/5** |
| 0.55 | **3** | 4/5 |
| 0.60 | 5 | 4/5 |

**两类仍然重叠** —— U-05（"一亿元要不要董事会审批"）是 0.6533，
**比能答的最低分 0.5228 还高**。所以"0 误拒 + 5/5 拦住"的阈值**不存在**，
0.50 是权衡点。剩下 2 条（U-02、U-05）是**阈值解决不了的语义问题**：
它们与制度高度相关，只是条文里确实没有那一档答案 ——
要靠"回答前先反问"或更强的模型（属 Agent 层的活）。

### 问题 4：跨版本命中是"过"的，但仍然不能因此认为版本机制已被验证

`cross_version` 三条在两种 embedding 下都命中 2026 版。
真正保证"只命中现行版"的是 `DISTINCT ON` 的版本过滤（有单元测试与集成测试钉着），
而评测集这一项**验证的是两者的合成效果** —— 语料只有两版、差异明显，
所以它**不能证明**在"多版本、差异细微"的真实场景下也成立。

### 问题 4：跨版本目前是"过"的，但**不能因此认为版本机制没问题**

`cross_version` 三条全部命中 2026 版。原因是 2026 版的条文里数字不同
（四百元 vs 三百元），字面差异让哈希 embedding 恰好选中了新版。
**但这是运气，不是机制在起作用** ——
真正保证"只命中现行版"的是 `DISTINCT ON` 的版本过滤（那部分有单元测试与集成测试钉着），
而评测集这一项**验证的是两者的合成效果**。

## 四、这份评测的用途

1. **它是后续所有优化的对照组**：加混合检索、加重排、换更大的 embedding，
   每一项都要与这份数字对比，**而不是凭感觉说"更好了"**；
2. **它是回归入口的一道硬门槛**：`knowledge_eval.py --gate`
   已接进 `回归验收.ps1`（第 11 步）。门槛值写在 `GATES` 里，
   并注明"取实测值往下留余量"的理由；
3. **它是标定 `KNOWLEDGE_MIN_SCORE` 的唯一依据**：
   分数分布是量出来的，阈值不是拍的（见第三节问题 3）；
4. **它把"哈希 embedding 不行"从判断变成了数据**：
   面试时可以说"我量化过：哈希对口语化问法的 top_score 只有 0.025，
   而无关问题的最高分是 0.362 —— 两者重叠，不存在可用阈值；
   换真模型后能答的最低分 0.5228、无答案的最高分 0.6533，仍然重叠，
   所以 5 条无答案问题里注定有 2 条是阈值解决不了的"。

## 五、复现方式

```powershell
cd backend
# 前置：本机 Ollama 在跑（.\scripts\ollama.ps1 -Serve），且已拉模型（-Pull）
.venv\Scripts\python.exe scripts\knowledge_eval.py                          # 跑全量（真 embedding）
.venv\Scripts\python.exe scripts\knowledge_eval.py --quiet                  # 关掉应用日志
.venv\Scripts\python.exe scripts\knowledge_eval.py --category colloquial    # 只跑口语化
.venv\Scripts\python.exe scripts\knowledge_eval.py --min-score 0.5          # 换阈值重测
.venv\Scripts\python.exe scripts\knowledge_eval.py --embedding local --min-score 0.15  # 对比哈希
.venv\Scripts\python.exe scripts\knowledge_eval.py --save baseline.json     # 存基线
.venv\Scripts\python.exe scripts\knowledge_eval.py --compare baseline.json  # 与基线对比
.venv\Scripts\python.exe scripts\knowledge_eval.py --gate --quiet           # 质量门禁（回归入口用）
```

脚本**先清掉上一次的 `EVAL-` 残留**、再自建临时账号与制度文档，跑完自清理，
不污染开发库。**连跑两次数字应当完全一致**（这是"自清理生效"的判据）。

> 报告头会写明这次用的是**哪个向量空间**（`embedding：...`）——
> 哈希与真模型的数字不可比，一份不注明 embedding 的报告拿去做对比就是错的。

## 六、诚实边界（这些数字不能推出什么）

| 不能推出 | 为什么 |
| --- | --- |
| ~~"检索没问题"~~ | Recall 1.000 建立在 **3 份文档 / 27 个片段**的语料上，规模一大就会掉 |
| ~~"支撑率 1.000 说明不编造"~~ | 这是**抽取式兜底**的输出（原文摘录），它天然忠实。**接上真对话模型后这个数字一定会掉** —— 那才是它真正有意义的时刻 |
| ~~"版本机制已通过验证"~~ | 见问题 4 —— 目前仍是字面/语义差异帮了忙，真正保证现行版的是 `DISTINCT ON` 过滤 |
| ~~"拒答率 3/5 是缺陷"~~ | 拒答是**正确行为**；剩下 2 条是**阈值解决不了**的语义问题（见第三节问题 2） |
| ~~"Precision 0.500 很差"~~ | 语料只有 27 个片段，"top-5"几乎把整个知识库都捞回来了 —— 分母大而分子小是**语料规模的产物**，不代表真实场景 |

**下一步（按性价比排序）**：

1. **接真对话模型**（Ollama + `qwen2.5:7b`，配置里留了三个空位）——
   这是唯一能测出"引用支撑率在真模型下是多少"的路，也是 Agent/工具调用的前提；
2. **混合检索 + 重排**：`Precision@5 = 0.500` 说明一半上下文是噪声，
   而这两项正是冲着它去的，对比基准已经就位；
3. **那 2 条阈值拦不住的无答案问题**（U-02/U-05）：
   它们与制度**语义高度相关**，只是条文里没有那一档。
   靠阈值无解，得靠"回答前先反问"或更强的模型 —— 属于 Agent 层的活。
