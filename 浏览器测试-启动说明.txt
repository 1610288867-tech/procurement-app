企业采购审批系统 —— 浏览器测试启动说明
================================================================

一共四步，按顺序执行。所有命令都在这个目录下运行：

    D:\procurement-app


────────────────────────────────────────────────────────────────
最省事：直接双击（等于做完第 1 步 + 第 3 步）
────────────────────────────────────────────────────────────────

    启动项目.bat                 一键：Docker + 数据库 + 前后端，并打开浏览器
    scripts\启动-数据库.bat      只做第 1 步
    scripts\灌演示数据.bat       只做第 2 步
    scripts\启动-前后端.bat      只做第 3 步
    scripts\启动-后端.bat        只起后端（单独调试用）
    scripts\启动-前端.bat        只起前端（单独调试用）

  · 这些 .bat 只是把命令转发给同名 .ps1，**启动逻辑仍然只有一份**
  · 失败时窗口会停住不关，看完报错再关
  · 它们优先调用 PowerShell 7（pwsh）；机器上只有 5.1 时会提示一句再继续


────────────────────────────────────────────────────────────────
不想手点？让脚本替你点一遍
────────────────────────────────────────────────────────────────

    node scripts\浏览器自检.mjs

  · 前提：前后端已经在跑（第 3 步做完）
  · 它会自己起一个**无窗口**的 Edge（独立配置目录，不碰你自己的 Edge），
    真实走一遍：未登录跳转、登录后回原页、按角色渲染菜单、无权限提示页、
    显示/隐藏密码开关、新建品类、审批策略报错原文、预算的元⇄分
  · 零依赖，不需要装任何东西；退出码 0 = 11 项全过
  · 会往开发库写一条 SELFCHECK-* 前缀的品类和一条预算，方便你认出来

审批链的浏览器实测另有一个脚本（19 项，会截 5 张图，存到系统临时目录下 procurement-m6\，
脚本会把完整路径打出来）：

    node scripts\m6-页面实测.mjs                  （需要后端 8000 + 前端 5173 都在跑）

  · 注意：浏览器自检跑完会关掉那个无窗口 Edge；先跑它、再跑这一个，
    或者两个分开跑，不要同时跑。

两个脚本造出来的数据（品类 / 预算 / 申请）没有删除端点，统一用这个脚本清：

    cd backend
    .\.venv\Scripts\python.exe scripts\testdata_cleanup.py --dry-run   先看会删什么
    .\.venv\Scripts\python.exe scripts\testdata_cleanup.py             真删（默认只清页面实测那批）
    .\.venv\Scripts\python.exe scripts\testdata_cleanup.py --scope all 连浏览器自检那批一起清

  判据是**写死的测试前缀**：申请标题以「M6 页面实测」开头、品类 `TCAT-PAGE-` / `SELFCHECK-` /
  `TCAT-`、部门 `TDEP-`、账号 `t-`。**种子数据和你自己建的数据不在删除范围内。**


────────────────────────────────────────────────────────────────
第 1 步：启动 Docker 引擎与数据库
────────────────────────────────────────────────────────────────

    .\scripts\dev-up.ps1

  · 会自动启动 Docker Desktop（本项目刻意没开开机自启，所以每次开工都要拉一次）
  · 然后执行 docker compose up -d 起 PostgreSQL 容器
  · 等到容器变成 healthy 才返回
  · 第一次可能要 1-2 分钟；之后通常 10 秒内

  如果卡住：加 -ShowWindow 重跑，会显示 Docker Desktop 的窗口，看它报什么错。


────────────────────────────────────────────────────────────────
第 2 步（可选，但推荐）：灌入演示数据
────────────────────────────────────────────────────────────────

    .\scripts\seed.ps1

  · 幂等，反复跑安全，已存在的会跳过
  · 会建：4 个部门（含一个子部门）、2 个采购品类（5 级和 2 级审批）、
    2 个供应商、1 条 10 万元预算，以及 7 个演示账号（8 个角色，GM 由 admin 兼任）
  · 全新数据库上建议跑一次，否则页面上都是空的


────────────────────────────────────────────────────────────────
第 3 步：启动前后端
────────────────────────────────────────────────────────────────

    .\scripts\start.ps1

  · 会各开一个新窗口：后端（uvicorn）和前端（Vite）
  · 端口上已经有服务就跳过，不会起重复进程
  · 结束时会打印两个地址，并做一次真实的数据库就绪检查
  · 那两个窗口不要关 —— 关掉就等于停止服务


────────────────────────────────────────────────────────────────
第 4 步：浏览器打开
────────────────────────────────────────────────────────────────

    http://localhost:5173

  先登录（M3 起业务页要求登录，管理员页要求 ADMIN）：

    用户名      admin
    口令        Dev-Passw0rd!        ← 仅本地演示数据

  其它演示账号（口令同上）：

    requester     REQUESTER     申请人
    dept-manager  DEPT_MANAGER  部门主管
    dept-head     DEPT_HEAD     部门负责人
    procurement   PROCUREMENT   采购专员
    finance       FINANCE       财务
    receiver      RECEIVER      收货人

  用非管理员账号（如 requester）打开 /admin/... 会看到「无权限」提示页；
  这是前端守卫的体验优化，**后端每个接口也会独立校验**（换 Postman 也一样拦）。

  页面导航（M5/M6 的业务页都在侧边栏里）：

    登录          http://localhost:5173/login
    环境自检      http://localhost:5173/                   （公开，不用登录）
    我的申请      http://localhost:5173/requests           （需登录 + 账号有部门）
    我的待办      http://localhost:5173/approvals/tasks     （需登录；只显示现在轮到您的）
    合格供应商    http://localhost:5173/suppliers          （需登录；只读，不含已停用）
    采购品类      http://localhost:5173/admin/categories   （需 ADMIN；含审批规则编辑器）
    供应商管理    http://localhost:5173/admin/suppliers    （需 ADMIN；新增 / 停用）
    预算          http://localhost:5173/admin/budgets      （需 ADMIN）

  两点容易困惑的地方：

  · **没有部门的账号看不到「我的申请」**（例如 admin）。判据是"有没有部门"，
    不是"是不是管理员" —— 部门决定预算归属与审批链，没有它连草稿都建不出来。
    （目前给账号指定部门只能直接改库的 `users.department_id`：
    建号 / 改部门都还没有 HTTP 接口，属已知真债，见 PROGRESS.md。）
  · **审批入口所有人都有**（包括 admin）：审批与部门无关，GM 要审大额单。
    演示时用 dept-manager（李主管）登录 →「我的待办」。
    或签任务要先点「认领」，才会出现「通过 / 驳回」。

  接口文档（可选）：http://127.0.0.1:8000/docs


────────────────────────────────────────────────────────────────
想少敲一次：一条命令搞定第 1 步 + 第 3 步
────────────────────────────────────────────────────────────────

    .\scripts\dev-up.ps1 -WithApi -WithFrontend

  注意它**不包含**第 2 步的 seed；需要演示数据时单独跑一次 .\scripts\seed.ps1。


────────────────────────────────────────────────────────────────
收工
────────────────────────────────────────────────────────────────

  · 关掉 start.ps1 开的那两个窗口（或者在窗口里按 Ctrl+C）
  · 数据库可以留着不用关；要停就执行：

        cd D:\develop\procurement
        docker compose stop

  **千万不要用 docker compose down -v** —— 那会连数据卷一起删掉。


────────────────────────────────────────────────────────────────
脚本清单（都在 scripts\ 目录下）
────────────────────────────────────────────────────────────────

  dev-up.ps1    Docker 引擎 + 数据库（可加 -WithApi -WithFrontend 一并起应用）
  start.ps1     只起前后端（就是上面的第 3 步）
                加 -ApiOnly 只起后端，加 -WebOnly 只起前端
  run-api.ps1   只起后端（start.ps1 会调用它，也可以单独跑）
  run-web.ps1   只起前端（start.ps1 会调用它，也可以单独跑）
  seed.ps1      演示数据（幂等）
  浏览器自检.mjs   无窗口 Edge 跑一遍关键界面（11 项，退出码 0 = 全过）
  m6-页面实测.mjs  审批链的浏览器实测（19 项 + 5 张截图）
  清理测试数据：backend\scripts\testdata_cleanup.py（见上面「让脚本替你点一遍」）

  想只起一半时：
    .\scripts\dev-up.ps1 -WithApi         只起 Docker + 数据库 + 后端
    .\scripts\dev-up.ps1 -WithFrontend    只起 Docker + 数据库 + 前端

  分工：dev-up.ps1 管基础设施，start.ps1 管应用。
  -WithApi / -WithFrontend 只是转发给 start.ps1，逻辑没有第二份实现。


────────────────────────────────────────────────────────────────
出问题时先看这三条
────────────────────────────────────────────────────────────────

1) 页面显示「请求失败：500 —— 后端可能没启动」

   后端没跑。执行 .\scripts\start.ps1

   为什么会这样：Vite 代理在后端不可达时，返回的是**空响应体的 500**，
   而不是连接错误，所以看起来像后端有 bug。
   判断口诀：看响应体长度是不是 0 —— 是 0 就是前端根本没连上后端。


2) 页面显示「请求失败：503」或「数据库暂不可用」

   后端在跑，但连不上数据库。执行 .\scripts\dev-up.ps1 把数据库容器拉起来。


3) 端口被占用

   脚本会直接告诉你被哪个 PID 占了。8000 是后端，5173 是前端。
   先停掉占用的进程再跑：

        Stop-Process -Id <PID>


4) 登录时报「用户名或密码不正确」/「登录失败次数过多」

   先确认第 2 步的 seed 跑过（账号是 seed 建的）。
   连错 5 次会被锁 5 分钟 —— 这是登录限流，等窗口过去即可，
   不用重启服务（限流在进程内存里，重启也会清空）。


────────────────────────────────────────────────────────────────
环境要求（只在换机器时需要重新做一次）
────────────────────────────────────────────────────────────────

  需要的软件：
    · Windows 11 + Docker Desktop（Linux 容器后端）
    · Python 3.12
    · Node.js 20 以上

  本机这两样已经装好了，不用重做：
    · backend\.venv      已建好并装了依赖
    · frontend\node_modules  已装好

  换机器时按顺序做一次：

    cd backend
    py -3.12 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    $env:PYTHONUTF8 = "1"
    python -m pip install -r requirements.txt --only-binary=:all:
    alembic upgrade head

    cd ..\frontend
    npm install

  详细说明见 README.md 的「初始化与启动」一节。
