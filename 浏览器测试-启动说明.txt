企业采购审批系统 —— 浏览器测试启动说明
================================================================

一共四步，按顺序执行。所有命令都在这个目录下运行：

    D:\procurement-app


────────────────────────────────────────────────────────────────
第 1 步：启动 Docker 引擎与数据库
────────────────────────────────────────────────────────────────

    .\scripts\dev-up.ps1

  · 会自动启动 Docker Desktop（本项目刻意没开开机自启，所以每次开工都要拉一次）
  · 然后执行 docker compose up -d 起 PostgreSQL 容器
  · 等到容器变成 healthy 才返回
  · 第一次可能要 1-2 分钟；之后通常 10 秒内

  如果卡住：加 -ShowWindow 重跑，会显示 Docker Desktop 的窗口，看它报什么错。


────────────────────────────────────────────────────────────────
第 2 步（可选，但推荐）：灌入演示数据
────────────────────────────────────────────────────────────────

    .\scripts\seed.ps1

  · 幂等，反复跑安全，已存在的会跳过
  · 会建：4 个部门（含一个子部门）、2 个采购品类（5 级和 2 级审批）、
    2 个供应商、1 条 10 万元预算
  · 全新数据库上建议跑一次，否则页面上都是空的


────────────────────────────────────────────────────────────────
第 3 步：启动前后端
────────────────────────────────────────────────────────────────

    .\scripts\start.ps1

  · 会各开一个新窗口：后端（uvicorn）和前端（Vite）
  · 端口上已经有服务就跳过，不会起重复进程
  · 结束时会打印两个地址，并做一次真实的数据库就绪检查
  · 那两个窗口不要关 —— 关掉就等于停止服务


────────────────────────────────────────────────────────────────
第 4 步：浏览器打开
────────────────────────────────────────────────────────────────

    http://localhost:5173

  页面导航：

    环境自检      http://localhost:5173/
    合格供应商    http://localhost:5173/suppliers          （只读，不含已停用）
    采购品类      http://localhost:5173/admin/categories   （含审批规则编辑器）
    供应商管理    http://localhost:5173/admin/suppliers    （新增 / 停用）
    预算          http://localhost:5173/admin/budgets

  接口文档（可选）：http://127.0.0.1:8000/docs


────────────────────────────────────────────────────────────────
想少敲一次：一条命令搞定第 1 步 + 第 3 步
────────────────────────────────────────────────────────────────

    .\scripts\dev-up.ps1 -WithApi -WithFrontend

  注意它**不包含**第 2 步的 seed；需要演示数据时单独跑一次 .\scripts\seed.ps1。


────────────────────────────────────────────────────────────────
收工
────────────────────────────────────────────────────────────────

  · 关掉 start.ps1 开的那两个窗口（或者在窗口里按 Ctrl+C）
  · 数据库可以留着不用关；要停就执行：

        cd D:\develop\procurement
        docker compose stop

  **千万不要用 docker compose down -v** —— 那会连数据卷一起删掉。


────────────────────────────────────────────────────────────────
脚本清单（都在 scripts\ 目录下）
────────────────────────────────────────────────────────────────

  dev-up.ps1    Docker 引擎 + 数据库（可加 -WithApi -WithFrontend 一并起应用）
  start.ps1     只起前后端（就是上面的第 3 步）
                加 -ApiOnly 只起后端，加 -WebOnly 只起前端
  run-api.ps1   只起后端（start.ps1 会调用它，也可以单独跑）
  run-web.ps1   只起前端（start.ps1 会调用它，也可以单独跑）
  seed.ps1      演示数据（幂等）

  想只起一半时：
    .\scripts\dev-up.ps1 -WithApi         只起 Docker + 数据库 + 后端
    .\scripts\dev-up.ps1 -WithFrontend    只起 Docker + 数据库 + 前端

  分工：dev-up.ps1 管基础设施，start.ps1 管应用。
  -WithApi / -WithFrontend 只是转发给 start.ps1，逻辑没有第二份实现。


────────────────────────────────────────────────────────────────
出问题时先看这三条
────────────────────────────────────────────────────────────────

1) 页面显示「请求失败：500 —— 后端可能没启动」

   后端没跑。执行 .\scripts\start.ps1

   为什么会这样：Vite 代理在后端不可达时，返回的是**空响应体的 500**，
   而不是连接错误，所以看起来像后端有 bug。
   判断口诀：看响应体长度是不是 0 —— 是 0 就是前端根本没连上后端。


2) 页面显示「请求失败：503」或「数据库暂不可用」

   后端在跑，但连不上数据库。执行 .\scripts\dev-up.ps1 把数据库容器拉起来。


3) 端口被占用

   脚本会直接告诉你被哪个 PID 占了。8000 是后端，5173 是前端。
   先停掉占用的进程再跑：

        Stop-Process -Id <PID>


────────────────────────────────────────────────────────────────
环境要求（只在换机器时需要重新做一次）
────────────────────────────────────────────────────────────────

  需要的软件：
    · Windows 11 + Docker Desktop（Linux 容器后端）
    · Python 3.12
    · Node.js 20 以上

  本机这两样已经装好了，不用重做：
    · backend\.venv      已建好并装了依赖
    · frontend\node_modules  已装好

  换机器时按顺序做一次：

    cd backend
    py -3.12 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    $env:PYTHONUTF8 = "1"
    python -m pip install -r requirements.txt --only-binary=:all:
    alembic upgrade head

    cd ..\frontend
    npm install

  详细说明见 README.md 的「初始化与启动」一节。
